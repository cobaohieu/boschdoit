The BoschDoIt CLI by default starts the [TUI](/docs/tui) when run without any arguments.

```bash
boschdoit
```

But it also accepts commands as documented on this page. This allows you to interact with BoschDoIt programmatically.

```bash
boschdoit run "Explain how closures work in JavaScript"
```

---

### tui

Start the BoschDoIt terminal user interface.

```bash
boschdoit [project]
```

#### Flags

| Flag         | Short | Description                                |
| ------------ | ----- | ------------------------------------------ |
| `--continue` | `-c`  | Continue the last session                  |
| `--session`  | `-s`  | Session ID to continue                     |
| `--prompt`   |       | Prompt to use                              |
| `--model`    | `-m`  | Model to use in the form of provider/model |
| `--agent`    |       | Agent to use                               |
| `--port`     |       | Port to listen on                          |
| `--hostname` |       | Hostname to listen on                      |

## Commands

The BoschDoIt CLI also has the following commands.

---

### agent

Manage agents for BoschDoIt.

```bash
boschdoit agent [command]
```

---

### attach

Attach a terminal to an already running BoschDoIt backend server started via `serve` or `web` commands.

```bash
boschdoit attach [url]
```

This allows using the TUI with a remote BoschDoIt backend. For example:

```bash
# Start the backend server for web/mobile access
boschdoit web --port 4096 --hostname 0.0.0.0

# In another terminal, attach the TUI to the running backend
boschdoit attach http://10.20.30.40:4096
```

#### Flags

| Flag        | Short | Description                       |
| ----------- | ----- | --------------------------------- |
| `--dir`     |       | Working directory to start TUI in |
| `--session` | `-s`  | Session ID to continue            |

---

#### create

Create a new agent with custom configuration.

```bash
boschdoit agent create
```

This command will guide you through creating a new agent with a custom system prompt and tool configuration.

---

#### list

List all available agents.

```bash
boschdoit agent list
```

### auth

Command to manage credentials and login for providers.

```bash
boschdoit auth [command]
```

---

#### login

BoschDoIt is powered by the provider list at [Models.dev](https://models.dev), so you can use `boschdoit auth login` to configure API keys for any provider you'd like to use. This is stored in `~/.local/share/boschdoit/auth.json`.

```bash
boschdoit auth login
```

When BoschDoIt starts up it loads the providers from the credentials file. And if there are any keys defined in your environments or a `.env` file in your project.

---

#### list

Lists all the authenticated providers as stored in the credentials file.

```bash
boschdoit auth list
```

Or the short version.

```bash
boschdoit auth ls
```

---

#### logout

Logs you out of a provider by clearing it from the credentials file.

```bash
boschdoit auth logout
```

---

### github

Manage the GitHub agent for repository automation.

```bash
boschdoit github [command]
```

---

#### install

Install the GitHub agent in your repository.

```bash
boschdoit github install
```

This sets up the necessary GitHub Actions workflow and guides you through the configuration process. [Learn more](/docs/github).

---

#### run

Run the GitHub agent. This is typically used in GitHub Actions.

```bash
boschdoit github run
```

##### Flags

| Flag      | Description                            |
| --------- | -------------------------------------- |
| `--event` | GitHub mock event to run the agent for |
| `--token` | GitHub personal access token           |

### mcp

Manage Model Context Protocol servers.

```bash
boschdoit mcp [command]
```

---

#### add

Add an MCP server to your configuration.

```bash
boschdoit mcp add
```

This command will guide you through adding either a local or remote MCP server.

---

#### list

List all configured MCP servers and their connection status.

```bash
boschdoit mcp list
```

Or use the short version.

```bash
boschdoit mcp ls
```

---

#### auth

Authenticate with an OAuth-enabled MCP server.

```bash
boschdoit mcp auth [name]
```

If you don't provide a server name, you'll be prompted to select from available OAuth-capable servers.

You can also list OAuth-capable servers and their authentication status.

```bash
boschdoit mcp auth list
```

Or use the short version.

```bash
boschdoit mcp auth ls
```

---

#### logout

Remove OAuth credentials for an MCP server.

```bash
boschdoit mcp logout [name]
```

---

#### debug

Debug OAuth connection issues for an MCP server.

```bash
boschdoit mcp debug <name>
```

### models

List all available models from configured providers.

```bash
boschdoit models [provider]
```

This command displays all models available across your configured providers in the format `provider/model`.

This is useful for figuring out the exact model name to use in [your config](/docs/config/).

You can optionally pass a provider ID to filter models by that provider.

```bash
boschdoit models anthropic
```

#### Flags

| Flag        | Description                                                  |
| ----------- | ------------------------------------------------------------ |
| `--refresh` | Refresh the models cache from models.dev                     |
| `--verbose` | Use more verbose model output (includes metadata like costs) |

Use the `--refresh` flag to update the cached model list. This is useful when new models have been added to a provider and you want to see them in BoschDoIt.

```bash
boschdoit models --refresh
```

### run

Run boschdoit in non-interactive mode by passing a prompt directly.

```bash
boschdoit run [message..]
```

This is useful for scripting, automation, or when you want a quick answer without launching the full TUI. For example.

```bash "boschdoit run"
boschdoit run Explain the use of context in Go
```

You can also attach to a running `boschdoit serve` instance to avoid MCP server cold boot times on every run:

```bash
# Start a headless server in one terminal
boschdoit serve

# In another terminal, run commands that attach to it
boschdoit run --attach http://localhost:4096 "Explain async/await in JavaScript"
```

#### Flags

| Flag         | Short | Description                                                        |
| ------------ | ----- | ------------------------------------------------------------------ |
| `--command`  |       | The command to run, use message for args                           |
| `--continue` | `-c`  | Continue the last session                                          |
| `--session`  | `-s`  | Session ID to continue                                             |
| `--share`    |       | Share the session                                                  |
| `--model`    | `-m`  | Model to use in the form of provider/model                         |
| `--agent`    |       | Agent to use                                                       |
| `--file`     | `-f`  | File(s) to attach to message                                       |
| `--format`   |       | Format: default (formatted) or json (raw JSON events)              |
| `--title`    |       | Title for the session (uses truncated prompt if no value provided) |
| `--attach`   |       | Attach to a running boschdoit server (e.g., http://localhost:4096)  |
| `--port`     |       | Port for the local server (defaults to random port)                |

### serve

Start a headless BoschDoIt server for API access. Check out the [server docs](/docs/server) for the full HTTP interface.

```bash
boschdoit serve
```

This starts an HTTP server that provides API access to boschdoit functionality without the TUI interface. Set `BOSCHDOIT_SERVER_PASSWORD` to enable HTTP basic auth (username defaults to `boschdoit`).

#### Flags

| Flag         | Description                                |
| ------------ | ------------------------------------------ |
| `--port`     | Port to listen on                          |
| `--hostname` | Hostname to listen on                      |
| `--mdns`     | Enable mDNS discovery                      |
| `--cors`     | Additional browser origin(s) to allow CORS |

```bash
boschdoit session list
```

##### Flags

| Flag          | Short | Description                          |

### stats

Show token usage and cost statistics for your BoschDoIt sessions.

```bash
boschdoit stats
```

#### Flags

| Flag        | Description                                                                 |
| ----------- | --------------------------------------------------------------------------- |
| `--days`    | Show stats for the last N days (all time)                                   |
| `--tools`   | Number of tools to show (all)                                               |
| `--models`  | Show model usage breakdown (hidden by default). Pass a number to show top N |
| `--project` | Filter by project (all projects, empty string: current project)             |

---

### export

Export session data as JSON.

```bash
boschdoit export [sessionID]
```

If you don't provide a session ID, you'll be prompted to select from available sessions.

---

### import

Import session data from a JSON file or BoschDoIt share URL.

```bash
boschdoit import <file>
```

You can import from a local file or an BoschDoIt share URL.

```bash
boschdoit import session.json
boschdoit import https://opncd.ai/s/abc123
```

---

### web

Start a headless BoschDoIt server with a web interface.

```bash
boschdoit web
```

This starts an HTTP server and opens a web browser to access BoschDoIt through a web interface. Set `BOSCHDOIT_SERVER_PASSWORD` to enable HTTP basic auth (username defaults to `boschdoit`).

#### Flags

| Flag         | Description                                |
| ------------ | ------------------------------------------ |
| `--port`     | Port to listen on                          |
| `--hostname` | Hostname to listen on                      |
| `--mdns`     | Enable mDNS discovery                      |
| `--cors`     | Additional browser origin(s) to allow CORS |

---

### acp

Start an ACP (Agent Client Protocol) server.

```bash
boschdoit acp
```

This command starts an ACP server that communicates via stdin/stdout using nd-JSON.

#### Flags

| Flag         | Description           |
| ------------ | --------------------- |
| `--cwd`      | Working directory     |
| `--port`     | Port to listen on     |
| `--hostname` | Hostname to listen on |

---

### uninstall

Uninstall BoschDoIt and remove all related files.

```bash
boschdoit uninstall
```

#### Flags

| Flag            | Short | Description                                 |
| --------------- | ----- | ------------------------------------------- |
| `--keep-config` | `-c`  | Keep configuration files                    |
| `--keep-data`   | `-d`  | Keep session data and snapshots             |
| `--dry-run`     |       | Show what would be removed without removing |
| `--force`       | `-f`  | Skip confirmation prompts                   |

---

### upgrade

Updates boschdoit to the latest version or a specific version.

```bash
boschdoit upgrade [target]
```

To upgrade to the latest version.

```bash
boschdoit upgrade
```

To upgrade to a specific version.

```bash
boschdoit upgrade v0.1.48
```

#### Flags

| Flag       | Short | Description                                                       |
| ---------- | ----- | ----------------------------------------------------------------- |
| `--method` | `-m`  | The installation method that was used; curl, npm, pnpm, bun, brew |

## Environment variables

BoschDoIt can be configured using environment variables.

| Variable                              | Type    | Description                                       |
| ------------------------------------- | ------- | ------------------------------------------------- |
| `BOSCHDOIT_AUTO_SHARE`                 | boolean | Automatically share sessions                      |
| `BOSCHDOIT_GIT_BASH_PATH`              | string  | Path to Git Bash executable on Windows            |
| `BOSCHDOIT_CONFIG`                     | string  | Path to config file                               |
| `BOSCHDOIT_CONFIG_DIR`                 | string  | Path to config directory                          |
| `BOSCHDOIT_CONFIG_CONTENT`             | string  | Inline json config content                        |
| `BOSCHDOIT_DISABLE_AUTOUPDATE`         | boolean | Disable automatic update checks                   |
| `BOSCHDOIT_DISABLE_PRUNE`              | boolean | Disable pruning of old data                       |
| `BOSCHDOIT_DISABLE_TERMINAL_TITLE`     | boolean | Disable automatic terminal title updates          |
| `BOSCHDOIT_PERMISSION`                 | string  | Inlined json permissions config                   |
| `BOSCHDOIT_DISABLE_DEFAULT_PLUGINS`    | boolean | Disable default plugins                           |
| `BOSCHDOIT_DISABLE_LSP_DOWNLOAD`       | boolean | Disable automatic LSP server downloads            |
| `BOSCHDOIT_ENABLE_EXPERIMENTAL_MODELS` | boolean | Enable experimental models                        |
| `BOSCHDOIT_DISABLE_AUTOCOMPACT`        | boolean | Disable automatic context compaction              |
| `BOSCHDOIT_DISABLE_CLAUDE_CODE`        | boolean | Disable reading from `.claude` (prompt + skills)  |
| `BOSCHDOIT_DISABLE_CLAUDE_CODE_PROMPT` | boolean | Disable reading `~/.claude/CLAUDE.md`             |
| `BOSCHDOIT_DISABLE_CLAUDE_CODE_SKILLS` | boolean | Disable loading `.claude/skills`                  |
| `BOSCHDOIT_CLIENT`                     | string  | Client identifier (defaults to `cli`)             |
| `BOSCHDOIT_ENABLE_EXA`                 | boolean | Enable Exa web search tools                       |
| `BOSCHDOIT_SERVER_PASSWORD`            | string  | Enable basic auth for `serve`/`web`               |
| `BOSCHDOIT_SERVER_USERNAME`            | string  | Override basic auth username (default `boschdoit`) |
